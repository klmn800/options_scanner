# Sector Archives

**Total Size:** ~85 GB across 19 databases
**Data Range:** July 29, 2025 - present (updated weekly)
**Last Documented:** April 2026

---

## Overview

This folder contains **19 sector-based SQLite databases** that store historical options data archived from production (`datalake.db`). Each database is a **self-contained, portable research archive** with complete context for analyzing sector-specific options behavior.

Archives are **updated every Friday night** by `data/health/db_archive_sector.py` as part of the automated three-tier retention strategy. Data older than the retention window is moved (or copied) from production into these sector databases, routed by symbol sector via the `symbol_metadata` table.

## How Archives Get Updated

The Friday night archive process (`db_archive_sector.py`) runs a three-tier retention strategy:

### Tier 1 - High-Frequency Flow Data (15-day retention)
- **Tables:** `flow_options_scans` (MOVE), `flow_alerts` (COPY)
- MOVE = deleted from production after archiving
- COPY = kept in production for ongoing reporting

### Tier 2 - Daily Summaries (30-day retention)
- **Tables:** `option_contracts` (MOVE), `option_symbol_summary` (MOVE), `flow_symbol_summary` (MOVE)
- `option_contracts` has hybrid logic: archives if expired OR older than 30 days

### Tier 3 - Reference Data (90-day retention)
- **Tables:** `historical_prices`, `earnings_events`, `news_symbol_sentiment`, `news_articles`, `market_daily_summary`
- COPY mode - data stays in production, also copied to archives
- `market_daily_summary` copied to ALL sector archives (market-wide context)
- `news_articles` routed by `symbols_mentioned` JSON parsing (multi-sector)

### Routing
Symbols are routed to sector archives based on `symbol_metadata.archive_db`. This column is set manually (Admin TUI or SQL) and preserved across daily metadata refreshes.

### Schedule
- **When:** Friday nights, starting ~7:30 PM after all daily operations complete
- **Timeout:** Monday 5:45 AM (59-hour window, allows full weekend)
- **Post-archive:** `db_optimize_sectors.py` runs ANALYZE on all sector DBs
- **Script:** `data/health/db_archive_sector.py --all-tiers`

## What's Inside Each Archive

Every archive contains **13-15 tables** with schemas identical to production `datalake.db`:

### Core Options Tables (3 tables)

**1. flow_options_scans** (36 columns)
- Intraday contract-level scans with Greeks, IV, and change tracking
- Multiple scans per day per contract
- Generated by Flow Monitor strategy

**2. option_contracts** (66 columns)
- Daily end-of-day OI analysis with time-series analytics
- Volume/IV percentiles, Greek momentum, OI build patterns
- Generated by Option Pipeline strategy

**3. flow_alerts** (41 columns)
- Options flow alerts with profitability tracking
- Generated by Flow Monitor strategy

### Summary Tables (2 tables)

**4. flow_symbol_summary** (12 columns)
- Daily alert-focused metrics for symbols with flow alerts
- Selective population (~50-100 symbols/day)
- Pre-computed rolling windows: alert_count_5d, alert_count_20d

**5. option_symbol_summary** (93 columns)
- Comprehensive symbol-level OI/IV/Greek summaries
- Universal coverage (~800 symbols daily)
- IV metrics by DTE bucket (front_month, 30dte, 45dte, 60dte)

### Reference Tables

6. **symbol_metadata** - Company fundamentals, sector classifications
7. **market_daily_summary** - Daily market metrics, Bull/Bear direction, regime classifications
8. **historical_prices** - OHLC daily price data for underlying symbols
9. **earnings_events** - Historical earnings dates with trading journal
10. **earnings_upcoming** - Pending earnings calendar
11. **news_symbol_sentiment** - Per-symbol news sentiment scores
12. **news_articles** - Article text and metadata
13. **alert_contract_tracking** - Alert profitability tracking data

### Airlines-Only Tables

14. **airline_options_tracking** - Airline-specific contract tracking (historical, from deprecated Airline Play strategy)
15. **airline_symbol_tracking** - Airline-specific symbol summaries (historical)

## How to Query These Archives

Use `tools/direct_db_query.py` with the `--db` flag:

```bash
# Explore a sector archive
python tools/direct_db_query.py --db data/sector_archive/airlines.db --tables
python tools/direct_db_query.py --db data/sector_archive/airlines.db --schema option_contracts

# Run SQL against a sector
python tools/direct_db_query.py --db data/sector_archive/technology.db \
  --sql "SELECT symbol, COUNT(*) FROM option_contracts GROUP BY symbol ORDER BY COUNT(*) DESC LIMIT 10"
```

### Example Queries

**Historical Pattern Discovery**
```sql
-- Study sector behavior during specific market events
SELECT trade_date, symbol, total_open_interest, put_call_ratio, iv_skew
FROM option_symbol_summary
WHERE trade_date BETWEEN '2025-08-15' AND '2025-08-30'
ORDER BY trade_date, put_call_ratio DESC;
```

**Strategy Backtesting**
```sql
-- Analyze flow alert profitability patterns
SELECT alert_level, COUNT(*) as alerts,
       AVG(final_quality_score) as avg_quality,
       AVG(signal_quality_score) as avg_signal_quality
FROM flow_alerts
WHERE significance_score > 5.0
GROUP BY alert_level;
```

**Cross-Sector Comparison**
```sql
-- Run same query across multiple sector archives to compare
SELECT trade_date,
       AVG(iv_front_month) as avg_iv,
       AVG(put_call_ratio) as avg_pcr
FROM option_symbol_summary
GROUP BY trade_date
ORDER BY trade_date;
```

### Common Mistakes

**Don't sum time-series data across dates:**
```sql
-- WRONG: Sums the same contract's OI across many days
SELECT symbol, SUM(open_interest) FROM option_contracts WHERE symbol='DAL';

-- CORRECT: Filter to specific date first
SELECT symbol, SUM(open_interest) FROM option_contracts
WHERE symbol='DAL' AND trade_date='2025-09-26';
```

**Don't expect perfect coverage in early data:**
- Data before Oct 2025 was migrated from expiration-based archives
- Some analytics columns may be NULL in older rows (expected)
- Data from Oct 2025 onward was archived directly from production (complete)

## Migration History

These archives were originally created in October 2025 by migrating data from expiration-based monthly archives (`archive_2025_07.db` through `archive_2025_10.db`) into sector-based databases. This was a two-phase process:

1. **Phase 1 (Oct 27, 2025):** Reorganized by sector using `symbol_metadata` routing
2. **Phase 2 (Oct 27, 2025):** Aligned all schemas to match production `datalake.db`

Since then, the archives have been continuously updated every Friday by the automated archiver. Two new sectors (`defense`, `nuclear`) were added after the initial migration.
