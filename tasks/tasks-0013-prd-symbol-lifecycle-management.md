### Notes

- No formal test framework. Validation via migration parity checks (Python list counts vs DB query counts) and dry-run onboarding of a test symbol.
- Migration must be staged: add columns → populate → verify parity → switch `get_specialty_list()` → run full trading day → remove Python literals.
- All database writes go to `data/datalake.db` (production). Query DB sync happens on normal schedule.
- **Dependency order:** Task 1 → Task 2 → Tasks 3, 6 (parallel) → Tasks 4, 5 (parallel, after 3). Task 2 has a human verification gate (run a full trading day before proceeding).
