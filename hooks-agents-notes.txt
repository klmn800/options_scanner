● 1. The Nightly Review — It's Not "Rigging It Up"

  What you're describing is actually a legitimate, supported pattern. Claude Code has a non-interactive mode
  specifically for this:

  claude -p "Review today's work in E:\options_scanner" --allowedTools Bash,Read,Grep,Glob

  The -p flag (or --print) runs headless — no interactive session, just executes and outputs. You could wrap this in
   a Windows Task Scheduler job that runs at 9 PM on weeknights. The flow would be:

  Task Scheduler (9 PM) → batch file → claude -p "your review prompt"

  The prompt could be something like:

  Review today's git log, check for any database anomalies in datalake_query.db (latest dates, row counts, null
  values in critical columns), verify archive health if it's Friday, and write a summary to
  logs/nightly_review_YYYY-MM-DD.md.

  That's not rigging anything — that's exactly what headless mode exists for. Autofix, CI integrations, and
  pre-commit hooks all use this same pattern. Your subscription usage covers it.

  The even more proper version: create a custom skill (/nightly-review) that encodes the full review checklist, then
   your scheduled task just runs:

  claude -p "/nightly-review" --allowedTools Bash,Read,Grep,Glob

  Now your review criteria are version-controlled in the skill file, not buried in a batch script.

  3. Skills vs Custom Agents — The Honest Answer

  They solve different problems, and the distinction matters for how I actually work:

  Skills are instructions for ME. When you invoke /db-health, that prompt gets injected into my current conversation
   context. I'm still me — I have our full conversation history, I can ask you follow-up questions, I see
  everything. It's like handing me a checklist while we're talking.

  Agents are separate workers I delegate TO. When I spawn a custom agent, it gets its own isolated context with only
   the system prompt you wrote for it. It can't see our conversation. It does its work, returns a result, and I
  relay it to you. It's like me calling a colleague in another room.

  When each adds more value to my workflow:
  ┌────────────────────────────────────────────┬─────────────┬──────────────┐
  │                 Situation                  │ Use a Skill │ Use an Agent │
  ├────────────────────────────────────────────┼─────────────┼──────────────┤
  │ You want to interact with the results      │ Yes         │ No           │
  ├────────────────────────────────────────────┼─────────────┼──────────────┤
  │ Task would bloat my context with data      │ No          │ Yes          │
  ├────────────────────────────────────────────┼─────────────┼──────────────┤
  │ Task can run in parallel with other work   │ No          │ Yes          │
  ├────────────────────────────────────────────┼─────────────┼──────────────┤

  Hooks — The Full Picture

  Hooks are shell commands that fire automatically at specific points in my workflow. You don't invoke them — they
  just run. Think of them as event listeners on my behavior.

  Where they live: ~/.claude/settings.json (global) or .claude/settings.json (project)

  The events you can hook into:
  ┌──────────────┬────────────────────────────┬──────────────────────────────────────────────┐
  │    Event     │       When it fires        │            What you'd use it for             │
  ├──────────────┼────────────────────────────┼──────────────────────────────────────────────┤
  │ PreToolUse   │ Before I use any tool      │ Block dangerous commands, validate inputs    │
  ├──────────────┼────────────────────────────┼──────────────────────────────────────────────┤
  │ PostToolUse  │ After I use a tool         │ Auto-format code, run linter, log what I did │
  ├──────────────┼────────────────────────────┼──────────────────────────────────────────────┤
  │ Notification │ When I need your attention │ Desktop toast, sound, Teams message          │
  ├──────────────┼────────────────────────────┼──────────────────────────────────────────────┤
  │ Stop         │ When I finish a response   │ Verify work is complete, run final checks    │
  └──────────────┴────────────────────────────┴──────────────────────────────────────────────┘
  The matcher field filters which tools trigger the hook. Without it, the hook fires on every tool use.

  Practical example for your project — Python syntax check after every edit:

  {
    "hooks": {
      "PostToolUse": [
        {
          "matcher": "Edit|Write",
          "hooks": [
            {
              "type": "command",
              "command": "python -m py_compile \"%FILE_PATH%\""
            }
          ]
        }
      ]
    }
  }

  Every time I edit or write a Python file, this automatically checks it compiles. If it fails (exit code != 0), I
  see the error immediately instead of discovering it later.

  More interesting example — enforce your decimal policy:

  {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "python tools/check_decimal_compliance.py \"%FILE_PATH%\""
          }
        ]
      }
    ]
  }

  You'd write a small script that scans for database INSERT/UPDATE calls without clean_database_row() — now it's
  enforced mechanically, not just by trusting me to remember.

  The three hook types:

  1. Command — runs a shell command. Most common. Exit code 0 = pass, exit code 2 = block the action.
  2. Prompt — sends the context to a fast model (Haiku) to make a yes/no decision. Good for fuzzy checks.
  3. Agent — spawns a full subagent to verify something. Heavy but powerful.

  What makes hooks different from skills/agents: Hooks are involuntary. I don't choose to run them — they fire
  automatically based on my actions. Skills and agents are intentional — either you or I choose to invoke them.
  Hooks are guardrails; skills and agents are capabilities.

  For your project, the highest-value hooks would be:
  - PostToolUse on Edit/Write → syntax check Python files
  - PostToolUse on Bash → log all commands I run to a file (audit trail)
  - Notification → Windows toast when I finish a long task
